# Phase 1 Integration Plan

Last updated: 2026-09-14

## Purpose

Phase 1 turns the known integration risks from `docs/PLAN.md`, `docs/requirements.md`, and `docs/gap-closing-plan-details.md` into verifiable contracts and canaries. Android and OneDrive work has advanced beyond its original spikes. The remaining Windows work will implement the production-oriented PowerShell path but must verify it against disposable inputs and leave the live Hermes job paused.

## Phase 1 Outcomes

Phase 1 is complete when the project has:

- A confirmed Android extraction strategy using a provider abstraction, with local Google AI Edge APIs or LiteRT-LM as the default provider and optional OpenAI-compatible API providers configured through Settings.
- A defined Settings Model Selector contract for provider and model selection.
- A working Microsoft Graph upload spike that writes a normalized receipt JPEG first and then publishes its complete Version 2 JSON handoff.
- A confirmed Hermes-to-PowerShell execution contract.
- A copied-workbook Excel COM canary that fills the first safe transaction row, preserves native workbook content, and verifies missing-month and summary integration.
- A deterministic duplicate/similar-record detection rule tested against the monthly worksheet layout.
- Updated project docs showing the chosen integration decisions, remaining risks, and any implementation constraints discovered by the spikes.

## Non-Goals

- Do not build the full Android MVP UI in Phase 1.
- Do not automate the real production workbook directly; use a copy for all workbook spikes.
- Do not upload the original/full-resolution receipt to OneDrive; upload only the required normalized JPEG below 200 KB.
- Do not depend on Amazon Photos links for MVP expense processing.
- Do not mark a spike done until the behavior is demonstrated, covered by focused tests where code exists, and checked against `docs/requirements.md`.

## Workstream Order

Run the workstreams in this order because later spikes depend on earlier contracts:

1. Define fixture data and handoff schema contract.
2. Spike OpenAI-compatible API extraction and provider selection.
3. Spike Microsoft Graph upload to OneDrive.
4. Spike Hermes PowerShell execution.
5. Implement and canary the confirmed workbook row mapping.
6. Spike duplicate and similar-record detection.
7. Spike Android local extraction on device.
8. Consolidate decisions and update Phase 2/3 plans.

- Focused unit tests and a disposable-path canary.

Exit criteria:
- Hermes can invoke the deterministic PowerShell action without an LLM.
- Re-running the same handoff file cannot create a second workbook row.
- Invalid and ambiguous files are preserved in the correct folder with an actionable reason.
- Empty runs are silent and reportable outcomes are delivered concisely to Discord.
- The created cron job remains paused after the canary.

## Workstream 5: Duplicate and Similar-Record Detection

Status: Behavior confirmed; implementation ready to start

Related requirements:
- REQ-W-003
- REQ-X-009 through REQ-X-012
- AC-004 through AC-006

Tasks:
- Implement exact duplicate detection by atomic local expense-id state.
- Parse only unambiguous trailing English workbook date suffixes and normalize merchant names conservatively without fuzzy or LLM matching.
- Treat matching date, two-decimal amount, and normalized merchant as an exact workbook duplicate that is skipped and archived.
- Treat matching date and amount with a different merchant as ambiguous and quarantine it for review.
- Implement the detection logic before workbook insertion.
- Test duplicate expense IDs, exact existing-row matches, same-date/same-amount merchant conflicts, ambiguous legacy descriptions, and multiple records within one batch.

Deliverables:
- Duplicate and similar-record rule document.
- Detection logic spike.
- Unit tests for exact duplicates and similar matches.

Exit criteria:
- Reprocessing the same expenseId never creates a duplicate row.
- Exact workbook duplicates are archived without insertion.
- Same-date/same-amount merchant conflicts are quarantined before insertion.
- Detection and routing are deterministic and fully covered by focused tests.
