# Receipt extraction fix and debug output

Status: ✅ Done (automated verification complete; live provider smoke test pending)

## Diagnosis and expected behavior

The multi-receipt change nested receipt items under a receipts array but omitted the closing brace for the outer schema properties. LM Studio therefore rejects a JSON Schema extraction request before the model runs. Provider verification uses a separate schema, so it can still pass.

The model prompt and JSON Schema require an object containing a receipts array. The extraction parser continues to accept that object, a plain array, and a legacy single receipt object. Each parsed transaction has a separate review and Version 2 handoff export.

## Implementation

1. Repair the receipt JSON Schema nesting and keep it shared by direct-image and OCR-text requests. Escape OCR control characters in chat request strings. Parse complete generated requests in unit tests and inspect the schema rather than asserting text fragments.
2. Preserve the raw assistant reply already carried by extraction results. Carry raw HTTP error bodies through remote-provider exceptions into manual-review state; use the transport error text when no response body exists. Keep the normal recovery message for manual entry.
3. Persist a default-off Debug output setting in SharedPreferences. Show its checkbox in Settings and pass the observed value to the Main receipt screen. Debug data stays in transient workflow state and is never written to logs or the export database.
4. Under receipt selection, show one read-only multiline raw-response textbox when Debug is enabled and an extraction attempt returned data or an error. Clear prior output when a new receipt is selected. Do not repeat the same raw response in every receipt review card.
5. After each export attempt that produces an export record, show the exact handoff JSON from ReceiptExportRecord.toVersion2Json() below that receipt's button. Label it Published only after the final OneDrive JSON succeeds; otherwise label it Generated, not published. Keep previews separate across receipts and stable on retry. A validation failure before record creation has no JSON preview.
6. Hide both debug textboxes as soon as Debug is disabled. The underlying review and export state remains available when Debug is enabled again.
