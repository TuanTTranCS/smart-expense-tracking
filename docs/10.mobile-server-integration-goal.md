## Summary

Use a separate mobile-server companion app, selected through this repo's saved provider profiles. Both receipt photos and typed expenses go directly to its configurable same-phone HTTP endpoint. Default the companion profile's endpoint to `http://127.0.0.1:8080/v1`, allow editing its port and API base path, and support an optional API key in both apps. The built-in on-device provider remains the app's default.

**Feasible, but requires changes in both projects.** The reviewed upstream revision, `a0ca94a9f79f1e5dbea0cb315f565f5512cae6b7`, accepts only string messages and disables images in its HTTP handler. Its underlying LiteRT-LM helper already supports images and a vision backend, providing a usable implementation path. [Server](https://github.com/techjarves/mobile-server/blob/a0ca94a9f79f1e5dbea0cb315f565f5512cae6b7/Android/src/app/src/main/java/com/server/edge/gallery/openai/OpenAiServer.kt), [inference helper](https://github.com/techjarves/mobile-server/blob/a0ca94a9f79f1e5dbea0cb315f565f5512cae6b7/Android/src/app/src/main/java/com/server/edge/gallery/ui/llmchat/LlmChatModelHelper.kt).

The workflow becomes:

**Receipt photo or typed expense → selected local endpoint → phone's model → existing validation, review, and export.**

## Companion-server changes

- Maintain a separate fork based on the reviewed revision; retain its license and attribution.
- Extend chat message content to accept both strings and OpenAI-style `text` / `image_url` parts. Support inline base64 receipt images; remote image downloads are outside this integration.
- Route decoded images and prompt text into the existing image-capable inference helper. Ensure the model engine was initialized with its vision backend; changing the conversation flag alone is insufficient.
- Retain `models` discovery and non-streaming `chat/completions` responses beneath the configured API base path (default `/v1`). Reject image requests clearly when the loaded model lacks vision support.
- Add an optional user-configured API key in mobile-server. With no key configured, allow requests without authentication. With a key configured, require `Authorization: Bearer <key>` for both discovery and extraction and reject missing or incorrect keys with HTTP 401 before inference. Store the key securely and exclude it from logs and error responses.
- Reset conversation state between expenses. Serialize inference and coordinate model unloading with active requests; cancellation and timeout must stop generation and release resources.
- Keep the companion bound to `127.0.0.1`, with tunnels disabled. Make its listening port and API base path configurable and persistent, defaulting to port `8080` and path `/v1`; show the active endpoint so the expense app can use the same values. Upstream currently binds all interfaces without authentication, so using a loopback client URL alone would not restrict server exposure. LAN and remote addresses remain outside this same-phone integration.
- Keep startup user-controlled in the companion app. Report running state only after successful startup, and show model readiness separately.

## Changes in Smart Expense Tracking

- Add an explicit **Same-phone server** profile category, reusing the existing OpenAI-compatible client, discovery, profile management, and immutable extraction snapshots.
- Make the companion profile's endpoint configurable and persistent in Settings, initially `http://127.0.0.1:8080/v1`. Allow editing its port and API base path to match mobile-server while requiring the literal host `127.0.0.1` for this category. Validate the endpoint before saving; use the saved base URL for discovery, verification, and extraction. Endpoint edits affect subsequent immutable request snapshots and cancel stale discovery/verification work. Permit cleartext narrowly for that host and reject redirects.
- Allow selection independently of the remote-provider opt-in. Keep the built-in on-device provider as the default and the fallback for deleted/missing profiles; adding or configuring mobile-server must not automatically select it. Server outages preserve drafts and offer retry/manual entry.
- Support an optional API key for the local server profile in the expense app. With no key configured, omit `Authorization` and send requests without a placeholder credential; with a key configured, send `Authorization: Bearer <key>` for discovery, verification, and extraction. Reuse secure per-profile credential storage, redaction, explicit key clearing, and immutable request snapshots. Show actionable authentication errors when the client key is missing or does not match the companion key. Preserve credential requirements for existing remote profiles.
- Add a **Prompt-only JSON** output mode that omits `response_format`. Upstream has no structured-output enforcement; retain the existing JSON prompts and output validation. Provider verification should validate the expected JSON object semantically rather than require identical whitespace.
- Send photos using the existing direct-image request format and typed expenses using string content. No OCR implementation is needed.
- Cap same-phone extraction concurrency at one and align its HTTP read timeout with the existing 180-second extraction deadline. Show actionable errors for stopped servers, missing models, busy inference, and invalid output.
- Migrate the profile database from v2 to v3 and provider-transfer format from v2 to v3 for profile category and output mode. Existing profiles/imports retain remote classification, credentials, selection, and opt-in behavior; imports still do not automatically select a provider.

## Verification and completion

- **Unit tests:** multimodal parsing and image rejection; vision initialization; independent expense conversations; cancellation and serialization; default/custom port and API-path persistence and request routing in both apps; invalid/non-loopback endpoint rejection and stale-operation cancellation; optional-key behavior in both apps (no-key requests omit authentication, matching keys succeed, missing/wrong keys return 401 before inference, secure storage/redaction, and key clearing); credential-free local-profile transfer; JSON request/response handling; built-in default, selection and migration compatibility; timeout and recovery behavior.
- **Integration checks:** model discovery, typed extraction, and single-photo extraction at the default and a custom same-phone endpoint, with authentication disabled and with matching keys; authentication failure/recovery with missing or incorrect keys; multiple transactions in one image, mixed batches, server restart with saved endpoint/auth settings, and invalid JSON blocking export.
- **Physical-phone validation:** confirm the selected vision model works offline after provisioning; record extraction accuracy, latency, memory pressure, and companion background behavior. HTTP compatibility alone does not establish model quality.
- Run shared and Android unit tests, relevant device tests, and debug builds for both apps.
- Implement against the aligned three-category requirements and `AC-052..060`, document the integration, update both status trackers, and add brief README setup instructions once supported. Mark completed implementation tasks ✅ Done while tracking outstanding device validation separately.

**Boundaries:** companion app plus direct-image support, as selected; no embedded server, OCR, public tunnel, automatic model download, or changes to the expense handoff format.
