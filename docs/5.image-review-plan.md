# Selected receipt image review plan

Status: ✅ Done (automated verification complete; physical-device check pending)

Last updated: 2026-09-21

## Goal

Let the user verify which receipt image the Android app is extracting. After a receipt is selected and preprocessing finishes, Main will show a compact image-review affordance. Activating it will open the complete processed image.

The preview is not a second conversion and is not the later export normalization result. It displays the exact `ReceiptImage` supplied to the extraction pipeline under `REQ-A-002A`:

- When oversized-image reduction is enabled and the source is larger than 200 KB (204,800 bytes), show the reduced JPEG below 200 KB.
- When reduction is disabled or the source does not exceed the threshold, show the original selected bytes.

This work implements `REQ-UI-007` and `AC-032` without changing the OneDrive image-first export contract.

## UX behavior

1. Keep the existing **Choose receipt** action. Once the picker result has loaded and preprocessing succeeds, show a compact thumbnail with a clear **Review selected image** label; a labeled button is an acceptable fallback if thumbnail rendering is unavailable.
2. Make the thumbnail or button one accessible click target with a content description that identifies it as the selected receipt preview.
3. Open a full-screen Compose surface when activated. Render the complete image with its aspect ratio preserved and no cropping, on a contrasting background.
4. Provide a visible close action and support system Back. Closing the viewer returns to the unchanged extraction/review state.
5. Keep the affordance visible while extraction is running and while extracted receipt cards are reviewed, including when one image produces multiple transactions.
6. A new picker result immediately clears the prior preview before loading. Successful loading replaces it with the new processed image. Picker cancellation leaves the current workflow unchanged; a failed new selection shows the existing processing error but must not display the previous receipt as though it were current.
7. Main-to-Settings-to-Main navigation preserves the current preview through the existing navigation-scoped workflow ViewModel. The image remains device-local and is not written to logs, saved-state bundles, or new persistent storage by this feature.

## Implementation design

### 1. Return the loaded image with the extraction result

Refactor the receipt-loading boundary so `ReceiptImageLoader.load(uri, reduceIfOversized)` runs once per selection. Return a small operation result containing both that processed `ReceiptImage` and the list of `ReceiptReviewState` values produced by `ReceiptExtractionController`.

Do not reopen the content URI or rerun compression for the preview. One `ReceiptImage` instance must be the source for both extraction and display, preventing a mismatch between what the model receives and what the user reviews.

### 2. Add navigation-stable preview state

Extend `ReceiptWorkflowUiState` with transient selected-image data needed by the Compose UI, including the processed bytes and MIME type. Clear this state at the start of a nonblank new selection, populate it as soon as image loading succeeds, and replace it atomically for subsequent selections.

Keep full-screen visibility as short-lived UI state in Compose or the workflow state. Do not place image bytes in `SavedStateHandle`, Room, preferences, logs, or export JSON. Existing `sourceImageUri` behavior for export stays unchanged.

### 3. Render the compact and full-image views

Decode the processed bytes for display off the main thread or through a remembered result keyed by the selected-image identity. Add a compact, aspect-ratio-preserving thumbnail to `ReceiptWorkflowScreen` below **Choose receipt** and before extraction diagnostics/review cards.

Open the viewer from the thumbnail using a full-screen dialog or dedicated Compose overlay. Use fit/contain scaling so every edge of the receipt remains visible without cropping. Release replaced bitmap references promptly. If decoding fails, keep extraction state intact, replace the thumbnail with an actionable review-unavailable message, and do not fall back to the original URI because that could show different bytes.

### 4. Preserve existing contracts

- Continue snapshotting the preprocessing setting when a selection starts.
- Do not alter extraction request construction, multiple-transaction review, manual-entry recovery, or provider privacy behavior.
- Do not change export-time JPEG normalization, deterministic OneDrive paths, or Version 2 JSON publication.
- Do not copy receipt content into diagnostics, analytics, or accessibility text.

## Test plan

### Unit tests

- An oversized input with reduction enabled returns and stores the same reduced JPEG bytes used by the extractor, and the byte count is strictly below 200 KB.
- A small input, and an oversized input with reduction disabled, stores the original selected bytes.
- Starting a new nonblank selection clears the prior preview; success installs the new image and failure leaves no stale preview.
- Picker cancellation does not clear the current workflow because `importReceipt` is not invoked for a null picker result.
- One processed preview is retained when extraction returns multiple receipt review cards.
- Main/Settings navigation continues to use the same `ReceiptWorkflowViewModel` state.

### Compose UI tests

- No image-review affordance appears before a successful image load.
- The thumbnail or **Review selected image** button appears after loading and exposes a stable content description.
- Activating it opens the full-image viewer; the visible close action and system Back dismiss it without changing review fields or export state.
- Choosing a replacement updates the rendered image and does not reveal the previous receipt.
- Loading, manual-entry, multiple-receipt, and debug-output layouts remain usable with the preview present.

### Verification commands

Run the shared JVM tests, Android app unit tests, Compose test compilation, and debug APK assembly using the repository's established Gradle configuration. Confirm the final build succeeds before marking this plan implemented.

Perform a physical-device check with one image above 200 KB and one below the threshold. For the oversized case, verify that the viewer shows the visibly processed image and that extraction/review/export still complete normally.

## Completion checklist

- `REQ-UI-007` and `AC-032` have focused automated coverage.
- The preview and extraction use the same processed bytes.
- Full-image review works with close and Back, preserves aspect ratio, and does not crop the receipt.
- Replacement, failure, cancellation, navigation, and multiple-transaction behavior match this plan.
- Shared and Android unit tests pass, Compose tests compile, and the debug app builds.
